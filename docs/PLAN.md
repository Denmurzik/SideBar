# SideBar — план

Статус: **исследование (этап 0) завершено 2026-10-22**, итоги — раздел 5; следующий шаг — M1. Решения согласованы
в сессии grill-me 2026-10-22 и уточнены по результатам спайков.
Контекст по Quick Share — `HANDOFF.md` (исторический, реверс-инжиниринг `nearby_share.exe`).

## 1. Что это

Нативная панель-карточка для Windows 11, выезжающая с правого края основного монитора (макет — ниже):

- курсор в ~1 см от правого края → панель слегка выглядывает («peek»);
- курсор касается края → панель выезжает полностью;
- курсор ушёл с панели → через короткую задержку прячется (не прячется во время drag или передачи).

Внутри две зоны:

1. **Верх — Quick Share.** В покое — полупрозрачный монохромный логотип Quick Share. Перетащил файлы →
   зона превращается в список найденных устройств → клик → отправка с прогрессом. Плюс полный приём
   файлов (см. ниже). Протокол — **своя реализация**.
2. **Низ — временная стопка** для drag-and-drop между приложениями. Файлы лежат стопкой со смещением.
   Только промежуточный буфер: принятые по Quick Share файлы сюда **не** попадают.

В фоне — минимум ОЗУ. Все анимации панели и внутри неё — **пружинные, как у Apple** (spring-физика,
без линейных/ease-кривых, прерываемые: новая цель подхватывает текущую скорость).

### Макет (эскиз пользователя, 2026-10-18, `docs/design/sketch-2026-10-18.jpg`)

```
 peek (курсор ≤1 см от края,          open (курсор коснулся края)
 на высоте карточки)
 ┌──────────────────────────┐▕       ┌──────────────────────────┐
 │                          │▕       │                   ╭────╮ │
 │                        ↖ ▐│ ← край│                   │ QS │ │  плитка Quick Share
 │                          ▐│ карточки                  ├────┤ │
 │                          │▕       │                   │▤▤  │ │  плитка-стопка (пунктир)
 │                          │▕       │                   ╰────╯ │
 └──────────────────────────┘        └──────────────────────────┘
```

- Не панель во всю высоту, а **компактная плавающая карточка** со скруглёнными углами, по вертикали **по центру**
  правого края основного монитора, с небольшим отступом от края. Положение фиксировано.
- Внутри — **две плитки** друг под другом: сверху Quick Share — **сплошная** обводка, в покое внутри
  полупрозрачный монохромный логотип в своём скруглённом квадрате; снизу — стопка (временный буфер) —
  обводка **пунктиром** (не сплошная!), файлы стопкой со смещением.
- **Peek** — из-за края выглядывает узкая полоска самой карточки на её высоте. Срабатывание peek/open — только когда
  курсор по вертикали в пределах карточки (± запас).
- **Список устройств — внутри плитки Quick Share**: после drop плитка показывает найденные устройства иконками
  (до 3–4), клик/drop на иконку — отправка; прогресс — кольцом вокруг иконки. Размер карточки не меняется.
- **Веер стопки — влево за пределы карточки**: клик по стопке → файлы пружиной разлетаются влево (превью + имя),
  каждый можно утащить; клик мимо — собираются обратно. Веер — отдельное окно того же типа (акрил, пружина).
- **Обводка карточки** — полупрозрачная серая линия толщиной 1 физический пиксель по контуру со скруглением,
  как системная рамка окон Windows 11 (свой оттенок для светлой и тёмной темы). Рисуется самой карточкой,
  не DWM-рамкой окна (DWM-граница выключена; толщина = 1/RasterizationScale epx).
- Размеры (настраиваемые константы, решения пользователя по демо S10, 2026-10-22): **ширина ×1.5 → 216 epx**,
  **высота ×1.7 → 469 epx** (от первого варианта 144×276); отступы 12 epx → плитки 192×216 epx;
  peek — видно ~10 epx карточки.
- Скругления как у окон Windows 11: карточка — **8 epx** (`OverlayCornerRadius`), плитки внутри — 4 epx
  (`ControlCornerRadius`); обводка 1 физ. px повторяет радиус карточки.

## 2. Согласованные решения

| Область | Решение |
|---|---|
| UI-стек | C#, WinUI 3 (Windows App SDK), unpackaged, NativeAOT + trimming |
| ОЗУ в фоне | Когда панель скрыта — `EmptyWorkingSet`/`SetProcessWorkingSetSize(-1,-1)`; цель — единицы МБ private working set в простое |
| ОС | Только Windows 11 |
| Монитор | Только основной монитор, правый край |
| Fullscreen | В полноэкранных приложениях не выезжает, кроме активного drag файла. Подавление: `QUNS_RUNNING_D3D_FULL_SCREEN`/`QUNS_PRESENTATION_MODE`, а `QUNS_BUSY` — только если окно переднего плана (не shell) покрывает весь монитор (`QUNS_BUSY` бывает и без fullscreen — S8) |
| Quick Share | Своя реализация протокола (по `google/nearby`, NearDrop и т. п.), отправка **и** приём |
| Медиумы v1 | Wi-Fi LAN (mDNS через Win32 `DnsService*` + TCP). BLE Fast Initiation (`0xFE2C`, 24-байтовый beacon, `docs/research/ble.md`) **отложен** (решение пользователя): Pixel 9 на него не реагирует, а с включённым экраном и «Все» виден по mDNS и без BLE. Wi-Fi Direct/hotspot — не в v1 |
| Видимость | «Свои устройства», «Все» (временно, ~10 мин), «Скрыто». «Контакты» — не в v1 |
| «Свои устройства» | Читаем сертификаты официального приложения: `preferences.json` (свои приватные) и leveldb `NearbySharePublicCertificateDatabase` (публичные устройств аккаунта) |
| Обновление сертификатов | Раз в сутки: если прошло ≥20 ч — при простое пользователя ≥5 мин запускаем `nearby_share.exe` с `SW_HIDE` (окон не видно), ждём `PublishDevice succeeded` в логе (~1.3 с), закрываем штатно `WM_QUIT` потоку окна (`WM_CLOSE` только прячет в трей; `TerminateProcess` — нельзя). Если прошло >48 ч — сразу. Запущенный не нами экземпляр не трогаем (S6) |
| Сосуществование | SideBar — единственный «экземпляр» этого ПК в эфире. Отдельного автозапуска у официального приложения нет; есть задача Планировщика `\Google\Quick Share Relaunch` (перезапуск после аварии) — не трогаем, завершаем приложение только штатно. Пока `nearby_share.exe` запущен (нами или пользователем) — свой стек на паузе |
| Деградация | Сертификаты нечитаемы/формат незнаком → режим «Все» (EVERYONE) с понятным сообщением |
| Входящие | От своих устройств — автоприём; от чужих — toast «Принять/Отклонить» с PIN. Файлы → «Загрузки», по завершении toast «Открыть / Показать в папке». При приёме панель кратко выглядывает (peek) и заезжает обратно |
| Анимации | Пружинные, прерываемые, с сохранением скорости. Выезд карточки — аналитическая пружина (ζ≈0.8) по кадрам `CompositionTarget.Rendering` + `SetWindowPos` (окно = карточка, S10 вариант B); анимации внутри карточки — Composition `Spring*NaturalMotionAnimation` |
| Стопка: хранение | Политика drop (S8, проверено на Проводнике/Chrome/Telegram): `CF_HDROP` с не временными путями → ссылкой (виртуальную копию, которую тоже отдаёт Проводник, игнорируем); `CF_HDROP` только во временных каталогах (`%TEMP%`, INetCache — Chrome) → берём `FileGroupDescriptorW`/`FileContents` и материализуем в `%LocalAppData%\SideBar\Shelf\<guid>\имя`; нет файлов, но есть `image/png|jpeg|webp`/`CF_DIB` (Telegram) → файл «Telegram <время>.<ext>». Имена в стопке уникальны («(2)»); «Без имени»/data:-URL → «Изображение <время>.<ext>». Drop-таргет — свой `IDropTarget` (`RegisterDragDrop` на дочерних окнах WinUI), т.к. WinUI не отдаёт нативный `IDataObject`. Состав стопки персистентен; исчезнувшие с диска файлы выпадают |
| Стопка: drag out | Тянешь стопку — уходят все файлы; клик раскрывает веером, можно тянуть по одному. **Только копирование**: `DragStarting.AllowedOperations = Copy` (иначе Проводник на том же томе делает optimized move оригиналов — найдено в S8). Элемент уходит из стопки только при `DropResult != None` |
| Настройки | Иконка в трее + контекстное меню: видимость, автозапуск, «Обновить сертификаты», выход. Отдельного окна нет |
| Автозапуск | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Язык UI | RU + EN по языку системы |
| Распространение | Личный проект. **Приватный** GitHub-репозиторий, лицензия GPLv3, релизы в GitHub Releases, установщик Inno Setup (без автообновления — проверка версии + ссылка) |

### Дефолты, выбранные без отдельного вопроса (можно поменять)

- Зона peek: 1 см → в пикселях по DPI монитора (`GetDpiForMonitor`, 96 DPI ≈ 38 px), по вертикали — высота карточки ± 1 см. Пока после старта собственного drag-out зажата ЛКМ — карточка остаётся открытой.
- Детект края: `WH_MOUSE_LL` на отдельном потоке (0 CPU в простое; работает и во время OLE-drag). Не «невидимая полоса-окно» — она перехватывала бы клики по скроллбарам развёрнутых окон.
- Тема: системная светлая/тёмная.
- **Материал — Acrylic** (решение пользователя): фон карточки — оконный `DesktopAcrylicBackdrop` (окно = карточка),
  элементы внутри — свои слои in-app `AcrylicBrush` с тинтом. Окно без non-client рамки (`WM_NCCALCSIZE` → 0,
  иначе 3 px `WS_DLGFRAME` просвечивает светлой линией), DWM-граница выключена, `DWMWCP_ROUND`.
- Приватные ключи из `preferences.json` — только в памяти, никогда не копируются на диск и не пишутся в логи.
- Весь протокольный стек — в том же процессе, но отдельной библиотекой без зависимостей от UI (тестируемость).
- CI: GitHub Actions — сборка, тесты, сборка Inno Setup-установщика на тег.

## 3. Архитектура (черновик)

```
SideBar.App          WinUI 3: окно панели, анимации, зоны, трей, toast, жизненный цикл, обрезка памяти
SideBar.Edge         WH_MOUSE_LL-хук, геометрия основного монитора, fullscreen-детект, состояния Hidden/Peek/Open
SideBar.Shelf        модель стопки, персистентность (JSON), материализация виртуальных файлов, IDataObject для drag out
SideBar.Nearby       протокол: mDNS (DnsServiceRegister/Browse, привязка к интерфейсу со шлюзом), OfflineFrame/V1Frame,
                     UKEY2, SecureMessage/D2D, Quick Share frames, отправка/приём, PIN, IShareIdentity
                     (Anonymous / Certificate); основа — spikes/nearby (75+ тестов, проверено на Pixel 9)
SideBar.Nearby.Certs чтение preferences.json + свой read-only ридер leveldb (без NuGet, AOT-safe; spikes/certs),
                     проверки формата (id==SHA256(secret), длины, tag), деградация в EVERYONE
SideBar.OfficialApp  контроль nearby_share.exe: детект чужого экземпляра, SW_HIDE-запуск, ожидание маркера в логе,
                     WM_QUIT; основа — spikes/official
tests/               юнит-тесты протокола (векторы из google/nearby), парсеров сертификатов, стопки
installer/           Inno Setup-скрипт
```

## 4. Риски после исследования

1. ~~Self-share на своём стеке~~ — **снят** (S4): Pixel 9 принимает подпись нашим ключом из сертификатов
   официального приложения, `PairedKeyResult SUCCESS` в обе стороны, приём без подтверждения.
2. **Формат сертификатов недокументирован** и может смениться с обновлением Quick Share (уже есть
   недокументированное поле 11). Митигирование: проверки формата + деградация в «Все»; парсер игнорирует
   неизвестные поля. Проверено на MSIX `NearbyShare` 1.0.2472.1.
3. **Штатный выход официального приложения через `WM_QUIT`** не документирован — может сломаться при смене
   Flutter-раннера. Фолбэк: не завершать принудительно, повторить цикл позже (`TerminateProcess` не используем).
4. **Гипотезы протокола, проверенные на одном устройстве** (Pixel 9, Android той версии): ранний обрыв сокета
   ломал приём на телефоне, `FileMetadata.id` обязателен. Другие производители (Samsung и т.п.) не проверены.
5. **Окно WinUI 3**: прозрачность окна недоступна (вне XAML — чёрное), поэтому выезд — движением окна (S10 B);
   120/144 Гц не проверены (монитор 60 Гц).
6. **BLE не работает как «будильник»** (S5) — пока телефон с заблокированным экраном ПК не увидит.
7. Ничего не проверено на 125/150% DPI (толщина обводки и пунктира — по расчёту).
8. **Монитор справа от основного**: окно карточки, сдвинутое за край, будет видно на соседнем экране (ревью #17) — решить в M1.

Требования к продуктовому коду по итогам ревью (25 пунктов, по этапам) — `docs/research/review-2026-10-22.md`;
каждый этап M1–M5 закрывает свои пункты с тестами.

## 6. Этапы реализации (после спайков)

1. **M1 — Каркас**: решение, проекты, CI, лицензия, README; панель с peek/open по краю, трей, автозапуск, обрезка памяти.
2. **M2 — Стопка**: drop, визуальная стопка, веер, drag out, персистентность, виртуальные файлы.
3. **M3 — Nearby «Все»**: отправка и приём по Wi-Fi LAN, список устройств в панели, прогресс, toast, PIN.
4. **M4 — «Свои устройства»**: сертификаты, автоприём, переключатель видимости, деградация.
5. **M5 — Официальное приложение**: пауза стека при его запуске, суточное обновление сертификатов.
6. **M6 — BLE (отложено)**: Fast Initiation / пробуждение — только если понадобится (S5).
7. **M7 — Релиз**: локализация RU/EN, Inno Setup, проверка новой версии, GitHub Release.
