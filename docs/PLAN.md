# SideBar — план

Статус: **план и исследование**, кода нет. Решения ниже согласованы в сессии grill-me 2026-10-22.
Контекст по Quick Share — `HANDOFF.md` (реверс-инжиниринг установленного `nearby_share.exe`).

## 1. Что это

Нативная панель для Windows 11, выезжающая с правого края основного монитора:

- курсор в ~1 см от правого края → панель слегка выглядывает («peek»);
- курсор касается края → панель выезжает полностью;
- курсор ушёл с панели → через короткую задержку прячется (не прячется во время drag или передачи).

Внутри две зоны:

1. **Верх — Quick Share.** В покое — полупрозрачный монохромный логотип Quick Share. Перетащил файлы →
   зона превращается в список найденных устройств → клик → отправка с прогрессом. Плюс полный приём
   файлов (см. ниже). Протокол — **своя реализация**.
2. **Низ — временная стопка** для drag-and-drop между приложениями. Файлы лежат стопкой со смещением.
   Только промежуточный буфер: принятые по Quick Share файлы сюда **не** попадают.

В фоне — минимум ОЗУ. Все анимации панели и внутри неё — **пружинные, как у Apple** (spring-физика,
без линейных/ease-кривых, прерываемые: новая цель подхватывает текущую скорость).

## 2. Согласованные решения

| Область | Решение |
|---|---|
| UI-стек | C#, WinUI 3 (Windows App SDK), unpackaged, NativeAOT + trimming |
| ОЗУ в фоне | Когда панель скрыта — `EmptyWorkingSet`/`SetProcessWorkingSetSize(-1,-1)`; цель — единицы МБ private working set в простое |
| ОС | Только Windows 11 |
| Монитор | Только основной монитор, правый край |
| Fullscreen | (дефолт) В полноэкранных приложениях не выезжает, кроме активного drag файла |
| Quick Share | Своя реализация протокола (по `google/nearby`, NearDrop и т. п.), отправка **и** приём |
| Медиумы v1 | Wi-Fi LAN (mDNS + TCP) + BLE Fast Initiation (`0xFEF3`) для «пробуждения». Wi-Fi Direct/hotspot — не в v1 |
| Видимость | «Свои устройства», «Все» (временно, ~10 мин), «Скрыто». «Контакты» — не в v1 |
| «Свои устройства» | Читаем сертификаты официального приложения: `preferences.json` (свои приватные) и leveldb `NearbySharePublicCertificateDatabase` (публичные устройств аккаунта) |
| Обновление сертификатов | Раз в сутки: если прошло ≥20 ч — при простое пользователя ≥5 мин запускаем `nearby_share.exe` свёрнутым, ждём `PublishDevice succeeded` в логе, аккуратно закрываем. Если прошло >48 ч — сразу |
| Сосуществование | SideBar — единственный «экземпляр» этого ПК в эфире. Автозапуск официального приложения отключаем; пока `nearby_share.exe` запущен (нами или пользователем) — свой стек на паузе |
| Деградация | Сертификаты нечитаемы/формат незнаком → режим «Все» (EVERYONE) с понятным сообщением |
| Входящие | От своих устройств — автоприём; от чужих — toast «Принять/Отклонить» с PIN. Файлы → «Загрузки», по завершении toast «Открыть / Показать в папке». При приёме панель кратко выглядывает (peek) и заезжает обратно |
| Анимации | Пружинные (Composition `SpringScalar/Vector3NaturalMotionAnimation`: DampingRatio + Period), прерываемые, с сохранением скорости |
| Стопка: хранение | Обычные файлы — ссылкой (путь). Виртуальные (`CF_FILEDESCRIPTOR`/`CF_FILECONTENTS` из браузера, мессенджеров) — материализуются в свою папку в `%LocalAppData%\SideBar\Shelf`. Состав стопки персистентен; исчезнувшие с диска файлы выпадают |
| Стопка: drag out | Тянешь стопку — уходят все файлы; клик раскрывает веером, можно тянуть по одному. После успешного drop элемент уходит из стопки; файл на диске копируется, не перемещается |
| Настройки | Иконка в трее + контекстное меню: видимость, автозапуск, «Обновить сертификаты», выход. Отдельного окна нет |
| Автозапуск | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Язык UI | RU + EN по языку системы |
| Распространение | Личный проект. **Приватный** GitHub-репозиторий, лицензия GPLv3, релизы в GitHub Releases, установщик Inno Setup (без автообновления — проверка версии + ссылка) |

### Дефолты, выбранные без отдельного вопроса (можно поменять)

- Зона peek: 1 см → в пикселях по DPI монитора (`GetDpiForMonitor`, 96 DPI ≈ 38 px). Ширина peek ~12 px, полная ширина ~340 epx.
- Детект края: `WH_MOUSE_LL` на отдельном потоке (0 CPU в простое; работает и во время OLE-drag). Не «невидимая полоса-окно» — она перехватывала бы клики по скроллбарам развёрнутых окон.
- Тема: системная светлая/тёмная.
- **Материал — Acrylic** (решение пользователя): фон панели — desktop acrylic (размывает то, что за окном,
  `DesktopAcrylicController`/`SystemBackdrop`), элементы внутри (зона Quick Share, карточки файлов стопки,
  список устройств) — свои слои Acrylic поверх (in-app `AcrylicBrush` с тинтом).
- Приватные ключи из `preferences.json` — только в памяти, никогда не копируются на диск и не пишутся в логи.
- Весь протокольный стек — в том же процессе, но отдельной библиотекой без зависимостей от UI (тестируемость).
- CI: GitHub Actions — сборка, тесты, сборка Inno Setup-установщика на тег.

## 3. Архитектура (черновик)

```
SideBar.App          WinUI 3: окно панели, анимации, зоны, трей, toast, жизненный цикл, обрезка памяти
SideBar.Edge         WH_MOUSE_LL-хук, геометрия основного монитора, fullscreen-детект, состояния Hidden/Peek/Open
SideBar.Shelf        модель стопки, персистентность (JSON), материализация виртуальных файлов, IDataObject для drag out
SideBar.Nearby       протокол: mDNS (DnsServiceRegister/Browse), BLE (WinRT advertisement publisher/watcher),
                     OfflineFrame/V1Frame, UKEY2, SecureMessage/D2D, Quick Share frames, отправка/приём, PIN
SideBar.Nearby.Certs чтение preferences.json + leveldb (read-only), проверка версии формата, деградация в EVERYONE
SideBar.OfficialApp  контроль nearby_share.exe: обнаружение запуска, отключение автозапуска, суточное обновление
tests/               юнит-тесты протокола (векторы из google/nearby), парсеров сертификатов, стопки
installer/           Inno Setup-скрипт
```

## 4. Главные риски

1. **Self-share на своём стеке может не заработать**: телефон должен принять наш ПК как «своё устройство»
   по сертификатам официального приложения. Это ядро всей затеи — проверяется первым.
2. **BLE-реклама на Windows ограничена**: `BluetoothLEAdvertisementPublisher` запрещает часть секций
   рекламы — неизвестно, можно ли воспроизвести Fast Initiation / рекламу Nearby.
3. **Формат сертификатов недокументирован** и может смениться с обновлением Quick Share.
4. **WinUI 3 + NativeAOT**: совместимость Google.Protobuf/CsWinRT с trimming; реальный фоновый объём ОЗУ.
5. **Окно и пружины**: двигать само окно через `SetWindowPos` каждый кадр рискует дёргаться. Вероятно,
   окно стоит на месте (прозрачное, клики сквозь пустую часть), а едет контент через Composition —
   нужна проверка прозрачного фона и click-through в WinUI 3 (спайк S10).
6. **Лицензии**: `google/nearby` — Apache 2.0 (совместима с GPLv3); лицензии NearDrop/NearShare и др. —
   проверить до заимствования кода.

## 5. Этап 0 — исследования (спайки), по убыванию риска

Каждый спайк — отдельный throwaway-код в `spikes/`, с явным критерием успеха.

| # | Спайк | Критерий успеха |
|---|---|---|
| S1 | Режим «Все»: свой отправитель на C# по Wi-Fi LAN (mDNS + UKEY2 + Quick Share frames) → Pixel 9 | Файл доходит до телефона |
| S2 | Режим «Все»: приём с Pixel 9 на свой стек | Файл принят, PIN совпадает с телефоном |
| S3 | Разбор `preferences.json` и leveldb официального приложения: структура сертификатов, соответствие protobuf из `google/nearby` | Извлечены свои приватные и публичные сертификаты устройств аккаунта; описан формат |
| S4 | «Свои устройства»: Pixel 9 видит наш ПК без режима «Все» и наоборот | Отправка/приём в self-share без подтверждения |
| S5 | BLE: публикация/приём Fast Initiation и рекламы Nearby через WinRT | Телефон «просыпается»/видит ПК без открытого Quick Share на нём |
| S6 | Контроль `nearby_share.exe`: где его автозапуск, запуск свёрнутым, детект `PublishDevice succeeded`, мягкое закрытие (`WM_CLOSE`), целостность leveldb после | Цикл обновления проходит без ручных действий; сертификаты обновлены |
| S7 | WinUI 3 + NativeAOT: пустое окно-панель + `EmptyWorkingSet` в скрытом состоянии, Google.Protobuf под AOT | Замер private working set в простое; время показа после обрезки < 100 мс |
| S8 | Edge + drag: `WH_MOUSE_LL` во время OLE-drag из Проводника, приём drop в WinUI, drag out нескольких файлов и виртуальных файлов из Chrome/Telegram | Все сценарии работают |
| S9 | Лицензии референсных реализаций | Таблица: что можно брать, что только читать |
| S10 | Пружинный выезд: прозрачное неподвижное окно + Composition-анимация контента vs `SetWindowPos` по кадрам; click-through пустой области | Плавно на 60/120/144 Гц, прерывание без рывков, клики проходят сквозь пустую часть |

**Точка решения после S1–S4**: если S4 не проходит — обсуждаем, оставаться ли на одном режиме «Все»
или вернуть отправку «своим» через `nearby_share.exe` (вариант A из HANDOFF).

## 6. Этапы реализации (после спайков)

1. **M1 — Каркас**: решение, проекты, CI, лицензия, README; панель с peek/open по краю, трей, автозапуск, обрезка памяти.
2. **M2 — Стопка**: drop, визуальная стопка, веер, drag out, персистентность, виртуальные файлы.
3. **M3 — Nearby «Все»**: отправка и приём по Wi-Fi LAN, список устройств в панели, прогресс, toast, PIN.
4. **M4 — «Свои устройства»**: сертификаты, автоприём, переключатель видимости, деградация.
5. **M5 — Официальное приложение**: пауза стека при его запуске, суточное обновление сертификатов.
6. **M6 — BLE**: Fast Initiation / пробуждение.
7. **M7 — Релиз**: локализация RU/EN, Inno Setup, проверка новой версии, GitHub Release.
