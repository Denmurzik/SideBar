# M2 — временная стопка: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Нижняя плитка карточки становится временным буфером drag-and-drop: файлы из любых приложений бросаются на неё, лежат стопкой со смещением, выносятся всей стопкой или по одному из веера, переживают перезапуск.

**Architecture:** Чистая логика — модель стопки (Id, имена, Owned/Reference, лимиты, сохранение), политика drop и выбор имён — в `SideBar.Core` с юнит-тестами. Win32/WinUI-слой в `SideBar.App`: нативный `IDropTarget` на дочерних окнах WinUI (WinUI не отдаёт нативный `IDataObject`), материализация виртуальных/временных файлов, визуальная стопка, вынос (только Copy), окно-веер. Источник проверенных приёмов — `spikes/ui/S8Edge` (`OleDrop.cs`, `MainWindow.xaml.cs`) и `spikes/ui/S8Drive` (автотест через `SendInput`), переносится, а не подключается.

**Tech Stack:** как M1 (.NET 10, WinUI 3 unpackaged NativeAOT, xunit.v3), `System.Text.Json` source generator (AOT), WinRT `StorageFile.GetThumbnailAsync` для превью.

**Spec:** `docs/PLAN.md` (§1, §2 «Стопка: хранение», «Стопка: drag out», «Макет»), `docs/research/review-2026-10-22.md` (#13–#16), `docs/research/ui.md` (S8), отложенные пункты M1 в `.superpowers/sdd/2026-10-22-m1-skeleton/progress.md` (SM_SWAPBUTTON, drag image над карточкой).

## Global Constraints

- Всё из Global Constraints M1 (`docs/superpowers/plans/2026-10-22-m1-skeleton.md`) остаётся в силе (AOT-safe interop, без активации окна, коммиты без трейлеров + push, сборки по одной под `.buildlock`, тесты — запуском exe).
- Политика drop (S8, PLAN §2): `CF_HDROP` с существующими не временными путями → элементы-ссылки (`Reference`), виртуальные файлы при этом игнорируются; `CF_HDROP` только во временных каталогах (`%TEMP%`, `%LOCALAPPDATA%\Temp`, `INetCache`) или нет `CF_HDROP` → `FileGroupDescriptorW`/`FileContents` материализуются (`Owned`); нет файлов, но есть `image/png|image/jpeg|image/webp` (HGLOBAL) или `CF_DIBV5`/`CF_DIB` → файл «Telegram yyyy-MM-dd HH-mm-ss.<ext>» (DIB → PNG через WinRT `BitmapEncoder`); только `application/x-td-forward` → отказ.
- Временные пути из `CF_HDROP` копируются (или открываются с `FileShare.Delete`) **синхронно внутри `Drop`** (#13); виртуальные — читаются из `IStream` внутри `Drop`, но пишутся на диск потоково (буфер 1 МиБ), не целиком в память (#14).
- Материализация: `%LocalAppData%\SideBar\Shelf\<guid>\<имя>`; лимиты: ≤ 100 элементов в стопке, один материализуемый файл ≤ 2 ГиБ; при превышении drop отклоняется (`DROPEFFECT_NONE`), в лог.
- Имена: уникальны в стопке («имя (2).ext»); «Без имени»/«Безымянный»/Untitled/Unnamed/Sin título/Sans titre/Unbenannt/Senza titolo без http(s)-URL → «Изображение yyyy-MM-dd HH-mm-ss.<ext>»; при одном виртуальном файле и http(s)-URL — последний сегмент пути URL; расширение при его отсутствии — по magic-байтам (jpg/png/gif/webp).
- Вынос: **только Copy** (`DragStartingEventArgs.AllowedOperations = Copy`, `RequestedOperation = Copy`). Элемент снимается со стопки только при `DropResult != None` **и** если drop был не на нашу же карточку/веер (#15). Файл `Owned` удаляется только если путь строго внутри `Shelf\` (`Path.GetFullPath` + префикс), не раньше чем через 30 с после снятия (приёмник может копировать асинхронно); `Reference` не удаляются никогда.
- Модель: у каждого элемента `Guid Id`, все операции — по Id (#16).
- Сохранение: `%LocalAppData%\SideBar\shelf.json` (source-gen JSON, запись атомарно через временный файл + `File.Move(overwrite)`); при старте элементы, чей файл исчез, выпадают; каталоги `Shelf\<guid>` без элемента удаляются.
- Пока зажата основная кнопка мыши (с учётом `SM_SWAPBUTTON`) — карточка не закрывается (как в M1).
- Визуальная стопка: до 3 верхних превью 96×96 epx со смещением 6 epx вниз-вправо и поворотом −4°/0°/+4°, сверху — последний добавленный; бейдж с количеством при > 1; иконка `ShelfEmptyIcon` скрыта, когда стопка не пуста. Превью — `StorageFile.GetThumbnailAsync(ThumbnailMode.SingleItem, 96)`, при ошибке — глиф `U+E8A5` (Document).
- Веер — отдельное окно того же стиля (Acrylic через `AlwaysActiveAcrylicBackdrop`, `DWMWCP_ROUND`, без активации, topmost), слева от карточки вплотную с зазором 8 epx, по вертикали по центру карточки; элементы — колонка до 8 видимых (прокрутка дальше), строка 48 epx: превью 40 epx + имя; появление — пружина по X из-за карточки; закрытие — клик вне веера/карточки, скрытие карточки, Esc.

## Review Focus

1. Drop нескольких файлов одновременно из Проводника (обычные пути) + повтор того же файла → два элемента-ссылки с уникальными отображаемыми именами, оригиналы не трогаются. Тест — Task 1 (модель) и Task 3 (автотест).
2. Chrome отдаёт `CF_HDROP` на temp-файл и виртуальный файл одновременно → ровно один `Owned`-элемент, файл в `Shelf`, не исчезает, когда Chrome удалит temp. Тест — Task 2 (политика), Task 3 (автотест T6 из S8Drive).
3. Вынос стопки на саму карточку/в веер или на плитку Quick Share → элемент остаётся в стопке. Тест — Task 4.
4. Файл-ссылка удалён/перемещён пользователем, пока лежит в стопке → при следующем показе/старте элемент выпадает, вынос не падает. Тест — Task 1 (prune) и Task 4.
5. Перезапуск приложения (и аварийное завершение посреди записи `shelf.json`) → стопка восстанавливается, файл состояния не битый. Тест — Task 1.
